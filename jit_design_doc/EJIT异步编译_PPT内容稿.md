## 1. 第一页：EJIT 异步编译 · Taskpool 调度

### 1.1 标题区

- **主标题**：EJIT 异步编译 · Taskpool 调度
- **副标题**：纯异步 · 单 Worker · 无锁并发 —— SRE 裸核 (aarch64_be) 无 C++ 线程库场景 · 2026.06 – 2026.11

### 1.2 左栏（三张卡片）

**卡片 1：问题背景**

| 引导词 | 说明 |
|---|---|
| 同步阻塞 | miss 时调用方全程等待 bitcode→特化→OrcJIT 编译, 空闲核无法参与 |
| 无去重 | 多调用方并发请求同一函数, 各自重复编译, 浪费 CPU |
| 裸核约束 | SRE aarch64_be 无 C++ 线程库 (thread/mutex/atomic), 仅原子变量+栅栏+task 原语 |

**卡片 2：关键技术**

| 引导词 | 说明 |
|---|---|
| 纯异步模型 | producer 入队即返回 fallback; 单 worker 跑在 EJitSreTask 平台 task (host/SRE 链接择一) |
| 无锁 MPSC 队列 | Vyukov 环形队列 1024 槽, 多 producer CAS 抢槽; 单 consumer 是无锁正确性硬约束 |
| Dedup 去重 | funcIndex 直接数组下标, CAS 占位 O(1); 冲突/队满 → 自动回滚 + fallback |
| 32 桶分桶缓存 | 每桶独立 RwLock: 读 tryRead 不等待 / 写 spin 等读者退场; rehash 只影响单桶 |
| 读计数外提 | lookup 返回 {fnPtr, bucket}, 调用方用完 release_read → 旧代码安全释放 |
| Version 懒失效 | toggle→version++ 单调递增: cache miss / 队列丢弃 / 不 publish; worker 双检查点挡竞态 |

**卡片 3：进展**

| 状态 | 内容 |
|---|---|
| ✓ | 单 worker 纯异步调度 + C ABI (compile_or_get / release_read / stats) |
| ✓ | 跨核共享单 worker: POD 共享 blob + CAS owner 选举, 生产 preset 钉核 6 |
| ✓ | 4K 页粒度跨核 seal (v5 ABI): slot 携带代码范围 + executableCoreMask 记忆 |
| ✓ | host 测试 EJITTaskPool / SharedTaskPool Tests: 注入式核 ID, 无真实线程 |
| △ | 待真机: 跨核 I/D-cache 一致性 · SRE_TaskDelete 真 join · worker 栈峰值实测 |

### 1.3 右栏：整体方案（流程图，顺时针环形数据流）

**分区标题条**：整体方案 · 纯异步单 Worker 调度 (producer 入队即返回 → worker 编译 → cache 跨核共享)

#### 泳道 1（上）：业务核 Core 0..N · Producer (AOT wrapper 调用)

第一行（左 → 右，正常路径）：

| 节点 | 标题 | 说明 | 样式 |
|---|---|---|---|
| A1 | ① 调用入口 | compile_or_get(funcIdx, dims) | 普通 |

#### 泳道 2（中）：跨核共享状态 · EJIT_SHARED_SECTION (全 POD + EJitAtomic · 同 VA 映射)

#### 泳道 3（下）：Worker 核

### 2.1 标题区

### 2.2 左栏（三张卡片）

**卡片 1：问题背景**

| 引导词 | 说明 |
|---|---|
| 多小区并存 | 每小区一个生命周期实例, 同一函数按小区特化出多版本, 版本数随活跃小区数增长 |
| 容量非瓶颈 | 单热点路径 2–5 KB << L1 I 32–64 KB; 风险在多版本叠加的 set 冲突与换入换出 |
| 布局半成品 | dispatcher 聚类与 cold 隔离已做, 多小区版本在代码池内的排布未按 cache 友好组织 |

**卡片 2：关键技术（已具备的消减基础）**

| 引导词 | 说明 |
|---|---|
| 多版本 Inline Cache | (funcIndex × dims) 直接索引, 每身份一槽, 多小区各自直跳特化版本 |
| 跨核共享 cell 表 | 表入共享段, toggle 置零即跨核失效; 各核命中同一份, 无每核回收会合 |
| Dispatcher 聚类 | 独立 .text.ejit_dispatch 段 64B 对齐, 单 line 容 1–4 个, 空间局部性命中 (PR #124) |
| Cold 隔离 | miss 函数体 → .text.unlikely, 减少热路径 cache 污染 (PR #124) |
| PMU 测量优先 | L1I_CACHE_REFILL / L1I_CACHE 定基线; <1% 健康, >5% 才需投入 (待上板) |
| 占用观测 | slot dump 整表 icache 占用报告, 支撑多小区版本体量评估 |

## 3. 绘制要点提醒

1. 两页版式完全一致（同模板），仅内容不同。
2. 第一页右栏是一个**顺时针闭环**：业务核(miss 入队) → TaskQueue → Worker(右→左) → publish 写回 Cache → 命中读回到业务核 ③。
3. 第二页右栏是**自上而下的框架**：版本来源 → I-cache 现状(留白) → 消减手段；中层的 6187/6188/6189 与"核间共享?"分支为虚线留白，是本页刻意保留的待填区。
4. 红色只做点缀不大面积使用；除两个红框强调节点外全部灰阶。
5. 所有留白处（＿＿＿）保持空白，供后续在 PPT 中直接填写。
